## Continuity checklist

For each project, keep canonical clone and build instructions, dependency versions, test commands and limitations, architecture/format documentation, licensing and third-party provenance, and a contribution path. Preserve historical release tags and user-data compatibility; document migrations and recovery before changing formats. Prefer reproducible fixtures and offline checks when feasible. Never publish secrets or private user data. Keep planned functionality separate from verified functionality.

Prioritize changes that make an independent fork possible without privileged services or maintainer knowledge. When a project is paused, record the last known working revision and unresolved risks rather than implying active support. Release tags and artifacts are separate from public development commits. No obligation to rename projects, recruit maintainers, or expand supported platforms is implied.

## Known review items

The portfolio website has no verified root license in the usual locations; clarify first-party code and content licensing with the owner, retaining the separate font license and third-party rights. Do not infer redistribution rights from public visibility. PDF Studio upstream versus downstream release links require provenance verification before changing download destinations. The Iowa curriculum requires qualified legal review before formal release. This is a maintenance checklist, not a completed source audit.
